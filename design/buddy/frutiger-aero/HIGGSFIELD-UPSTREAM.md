# Higgsfield upstream — point-by-point audit

Prepared **2026-10-10**. This is a documentation and prompt review. No generation, Blender mutation, connection change or runtime integration was performed. Sprout/Prism remains the selected direction; the running character is still Ribbon v001.

**Recommendation:** use Higgsfield when it supplies a useful editable starting point or reference. Keep an original Blender-authored mesh as an immediate alternative, with Blender responsible for the approved geometry, rig and export. Ship local assets and an accessible HTML interface.

## Verified product claims and session limits

The official [3D Jutsu guide](https://higgsfield.ai/blog/higgsfield-3d-jutsu) describes a standalone browser workspace, separate from the Blender plugin, with editable scene objects, lighting, cameras and timelines. It documents GLB import/export, static frames and MP4 output. The [Blender plugin guide](https://higgsfield.ai/blog/higgsfield-blender-plugin) describes scene building, model generation, character animation, images and video inside Blender. These are product capabilities, rather than proof that every operation is exposed through this session's bridge or suitable for Sprout.

The live host check found **Blender connected; 3D Blocking Studio not connected**. The current 3D model list includes Tripo, Meshy 6, Hunyuan, image/multiview, rigging, Kimodo and remesh entries. Those labels do not supply full input schemas, pricing or rig compatibility. The exposed bridge lacks `bl_estimate_generation`, a general schema-complete generation submission and a general motion-generation tool. Nothing in this documentation task requires another connection.

## Audit of the requested workflow

“Supported” below describes the documented product. “Conditional” means that the current tools, returned asset and our acceptance checks must also support the intended use. All production choices below are proposals.

Keep the untouched output, generation settings and provenance. Import into a staging collection; inspect scale, axes, origins, disconnected parts, normals, UVs and materials. Accept a candidate only after its small face and silhouette work. If unavailable or unsuitable, proceed with original local modeling.                           |

A generated video is a timing reference, not a GLB clip or verified lip-sync.                                                                                                                          |

Use `.glb`; `.gbl` is a typo.                                                                                                                                 |
| **No Higgsfield runtime**             | **Correct boundary.**                                          | Higgsfield belongs to authoring. A later R3F or Next host is optional packaging, not an upstream prerequisite.                                                              |

## Cost and submission boundary

The [plugin guide](https://higgsfield.ai/blog/higgsfield-blender-plugin) says its Generate button shows credit cost before submission; the [3D Jutsu guide](https://higgsfield.ai/blog/higgsfield-3d-jutsu) describes estimates before sending. That does not establish a callable estimate in this bridge. Discover the actual schema and a non-spending estimate before any future job. **Never submit generation merely to discover price.** If those capabilities are absent, record the gap and continue locally. The current task spends no generation credits.

## Decision for the consolidated prompt

Make generated input optional: **reference/proxy → optional candidate intake → Blender cleanup and fixed topology → canonical rig/clip proof → validated GLB → measured delivery optimization → existing browser and Electron proof**. Retain provenance, editable source, export manifest and recordings at each handoff. Use the [production runbook](PRODUCTION-WORKFLOW.md) for host integration and measured gates; this audit does not replace it or the full implementation prompt.
