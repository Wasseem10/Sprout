# Revision 6 panel: source study and implementation boundary

Date: 2026-10-10. This record covers the real `DesktopBuddy` presentation refinement. The panel uses original local CSS and a small React disclosure component; no glass package, screenshot-texture engine, second WebGL canvas or new runtime dependency was installed.

## Reference interpretation

Both rendered pages of the user's `refrence design.pdf` were inspected. Page 1 supplies the continuous rounded rim, single identity/state hierarchy and prominent composer/voice action. Page 2 supplies clear cyan edge light with restrained violet/coral reflections. The reference's low-contrast small text and three unexplained coloured controls are not copied.

The implementation retains the existing 96px pet. At the nominal native expanded size and 100% zoom, the window is 408×672 CSS pixels and its 8px outer padding leaves one 392×656 visible buddy frame. The conversation section below the 96px header is up to 560px high; that section includes the reading well and composer. Smaller viewports and native work-area clamping reduce the available height. The expanded surface visually joins the identity row and conversation section. The original native coordinator remains responsible for bounds acknowledgment, reversal, hidden-window settlement and presentation memory.

## Actual material and interaction

`src/buddy.css` paints a restrained cyan/violet/coral outer rim, narrow white highlight, inner bevel and soft shadow. A continuous opaque cloud-white gradient sits inside it. Text and live controls are separate HTML above that decoration. There is no blur or displacement on text, no duplicated conversation, no animated gradient/filter strength and no panel animation loop. Existing decorative shell transform/opacity remains with `useBuddyPanel`.

`DesktopBuddy` removes the second title block and long welcome. `BuddyDisclosure` supplies Ideas and Tools with normal Tab order, truthful disabled/toggle state, Escape-to-trigger focus and dismissal before existing modal actions. Existing suggestion and utility handlers are retained. Expanded voice control moves beside Send; collapsed voice access and immediate Stop remain. Shortcut guidance is accessible help rather than permanent duplicate copy. Main conversation text remains 18px, or 22px in Large mode.

Reduced-transparency/increased-contrast media preferences select a plain solid frame/reading surface. Forced colours use system colours; reduced motion preserves the existing static path. Unsupported preference queries leave the already opaque reading surface usable. Performance and contrast acceptance require the separately recorded actual browser/native checks; this source note does not certify them.

## Native compositing limit

The glossy appearance is a CSS approximation. It does not sample or optically refract other applications behind transparent Electron. [Electron's transparent-window documentation](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles#limitations) states that CSS blur applies to window web contents rather than underlying applications. [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) describes webpage backdrop-root boundaries. Adding an SVG filter would not cross that native boundary.

[Electron native Acrylic/Mica](https://www.electronjs.org/docs/latest/api/base-window#winsetbackgroundmaterialmaterial-windows) is a separate Windows 11 22H2+ system backdrop and was not enabled by this change. Any future native-material study must preserve the freestanding transparent pet, readable fallback, work-area bounds and voice timing. Desktop capture is not a runtime material source.
