## Result

The actual navy eye meshes now close into smooth, rounded upward arches. The old blue covers and separate closed-eye marks are removed from the selected export. Glints retract with closure; sleep holds the contented expression. One mixer coordinates blink, sleep and interrupted wake, with strict versioned bindings and matching idle/sleep PNG fallbacks. The body/core geometry, glass materials, rig and non-eye motion remain exact v004 data. The [asset handoff](ASSET-HANDOFF-v005.md) records the editable Blender source, reproducible scripts, hashes and deliberate eye-track exceptions.

The panel now reads as a thin glass sheet with sparse reflections instead of a thick coloured frame. Buttons share quieter inset highlights and shadows; readable local surfaces remain behind text. A matched real-component A/B comparison selected layered CSS glass. Rounded-edge RGB refraction first added a seam; the corrected-owner comparison offered too little visible benefit to justify its complexity. Final active-tilt inspection caught a backdrop-root defect: the finished opening animation isolated a child filter, so frost disappeared during perspective rotation. Moving the unchanged filter onto the animated glass element preserves its sampling without changing the coordinator or filtering text. The [glass study](../frutiger-aero/SPROUT-THIN-GLASS-STUDY.md) records the pinned MIT references, retained notice, measurements and comparison stills.

The expanded visual plane leans at up to 1.2° horizontally and 0.45° vertically, using perspective 1800px. The fixed layout/input surface and existing expand/collapse transform retain separate owners. Editing, menus, selection and keyboard navigation neutralize the effect; a held press freezes it. Hidden/offscreen, paused, reduced-motion, forced-colour and coarse-pointer states stay static. The settling loop stops when finished. Avatar gaze uses its untransformed layout slot, avoiding feedback from the parent's perspective.

Windows native drag regions suppress DOM pointer events, so a narrow read-only bridge observes the native move-loop begin/end messages. It freezes the visible plane during the loop and clears stale pointer intent afterward. Trusted-origin/main-frame checks, monotonic revisions and listener cleanup follow the existing visibility bridge. Hooks remain installed across normal close-to-tray and are released with the destroyed native window. No pointer polling or pointer-driven resize/position IPC was added. Other platforms retain ordinary DOM tilt guards; native move-loop integration is Windows-specific.

Visible product identity is **Sprout**, including the plain compact wordmark, frontend greeting, accessible labels, browser title and native tray/menu/window copy. [Identity classification](IDENTITY-v005.md) explains retained IPC/storage/environment/package names and backend-owned output that still uses historical branding.

## Timing and resource results

The final compiled index SHA256 is `998d575c8ea38075ddcda18569fe34a094189d104943f7c7e0111386256b78e9`. The renderer chunk and selected assets are unchanged by the final CSS correction. During the 8.156s first-tilt run, 482 Chromium feedback intervals have p95 **16.775ms**, maximum **83.340ms**, two above 20ms and one above 50ms. That is a failed first-use tail, despite ordinary frames meeting the 60Hz target. The explicit warmed run exercises both pointer directions before measurement: its 8.057s / 480-interval window has p95 **16.759ms**, maximum **33.286ms**, one above 20ms and none above 50ms. It passes the same gates; it does not erase the first-use hitch. The earlier v004 report measured p95 16.781ms / maximum 16.916ms over 5.862s without this explicit pointer sweep, so it is context rather than a matched tilt comparison.

Settled tilt leaves no pending decorative callback. Five panel cycles preserve live handle counts, allowing only the existing balanced transmission-target resize allocations. The final lifecycle run passes offscreen, hidden, minimized, restored and disposed checks. Both new eye morph arrays are explicitly deleted; the updated exact-signature assertion accounts for seven owned texture deletions instead of v004's five. Known pinned Three internal caches remain separately classified and become unusable after forced context loss. See the [timing review](../../../artifacts/glass-sprout-v005-final-warm/buddy-runtime-native/FINAL-TIMING.md) and [eye texture diagnosis](../../../artifacts/glass-sprout-v005-warm/buddy-runtime-native/RESOURCE-NOTES.md). ## Evidence limits

CSS can frost owned webpage backgrounds. Electron cannot use CSS backdrop blur to sample other desktop apps; native captures certify translucency and supported gloss, not OS-background refraction. The previous rectangular Acrylic result remains rejected. No desktop screenshot or duplicated conversation is used as a runtime material.

Timed Blink stills can land after reopening; they are not evidence of an exact closure peak. Actual-export CPU samples establish the peak and closed geometry, while the source sheet and motion recordings establish appearance. Headless eye rendering used SwiftShader and makes no performance claim. Native timing is recorded separately.

Actual Windows physical title dragging remains unverified. Registered native-message callbacks and their real IPC/consumer behavior pass a labelled fixture, including freeze/release and hook retention through close/hide/show. A bounded Sky drag over the visible native draggable-region overlay did not establish a completed begin/end pair or window movement. The [diagnosis](../../../artifacts/glass-sprout-v005-native-drag-debug/DIAGNOSIS.md) distinguishes that failed physical attempt from the passing callback fixture; input injection versus native hit testing was not resolved.

Voice checks use local oscillator/MediaRecorder/PCM fixtures through the existing production owner. Physical microphone/speaker behavior, live ElevenLabs, human screen-reader acceptance, other displays/DPI settings and packaged installation are not established by these tests.
